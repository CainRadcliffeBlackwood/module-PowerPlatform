関数いろいろ

formatNumber(数値, フォーマット[, ロケール])
　数値のフォーマットをコントロールする
　通貨スタイルにする場合はロケールに「ja-jp」を指定

empty(コレクション) / (文字列)
　コレクション/文字列が空であればTrue、そうでなければFalseを返す

first(コレクション) / (文字列)
　コレクションの先頭 / 文字列の先頭1文字を返す
　last関数もあり、これも同様

item()
　ループ内で使用
　そのコレクションの値を返す

skip(コレクション, 削除数)
　コレクションより、左から指定した数だけ要素を削除したコレクションを返す

take(コレクション, 取得数)
　コレクションより、左から指定した数だけのコレクションを返す

sort(コレクション)
　コレクションを昇順に並べ替える
　降順に並べたい場合は「reverse」関数でこれを囲う

createArray(要素1, 要素2, ...)
　文字列から配列を作成する
　通常、変数をアレイ型で宣言した時の初期値の中身として使用する

json(json文字列)
　json文字列をjson型に変換する

string(数値)
　文字列→数値に変換

addToTime(日付文字列, 加算数, 単位)
　指定した日付に対し、指定した単位の数だけ先の日付を返す

getFutureTime(加算数, 単位)
　現在の日付を起算値として、指定した単位の数だけ先の日付を返す

dayOfWeek(日付変数)
　日曜日を「0」～土曜日を「6」として、その日付変数の曜日を返す

perseDateTime(日付を示す文字列, タイムゾーン('ja-jp'), その日付文字列が採用しているフォーマット)
　日付を示す文字列を、PowerAutomateが認識できるフォーマットに変換する

formatDateTime(日付変数, 変換後フォーマット)
　日付変数を、指定したフォーマットに変換する

startOfMonth(日付変数)
　月初を取得する

range(初期値, 作成分)
　初期値から始まる連番を、作成分に指定した分だけ作成する

equals / greater / greaterOrEquals / less / lessOrEquals (値, しきい値)
　値としきい値の関係を判定する


日付の取扱
　「yyyy-MM-ddTHH:mm:ssZ(ISO 8601)」形式　※最後の「Z」はUTCを表す
　　※時間「H」：「H」で24時間形式、「h」で12時間形式。「th」または「tth」で「P9」「PM9」のように表示できる
　アクションを使用する場合、「現在の時刻を取得」→「タイムゾーンの変換」の順に組み立てる
　Excelからシリアル値で日付時刻を取得する場合
　　Excelからデータを持ってくるアクションで「詳細オプションを表示する」→「DataTime形式」を「ISO8601」に指定する
　　ただしこれをしてもUTCで取得するため注意

データソースをExcelにするときの注意点
　・Excelテーブルの制限
　　・列に主キー項目が含まれていなければならない
　　・列名をセル内改行してはいけない
　　・列名の先頭が数字で始まってはいけない
　　・列名にハイフンが含まれてはいけない
　　・非表示列を作成することができない
　　・xlsxファイルしか対応していない

アレイとJSON
　アレイの書式：[ Value1, Value2, ... ]
　　直接値を指定する方法：variables('ArrayName')?[index]
　　作成方法
　　　１．「変数を初期化する」→アレイ型で上記の記法で記述
　　　２．「データ操作」→「作成」より、式「CreateArray( Value1, Value2, ... )」を指定
　　要素追加方法
　　　「配列変数に追加」より追加
　　要素取り出し方
　　　「Apply to each」に、動的変数としてアレイを指定
　　　→内部のアクションに動的変数「現在のアイテム」を指定するか、式「item()」を指定
　JSONの形式：{ Key1:Value1, Key2:Value2, ... }

OData(Open Data Protocol)クエリ：複数の項目を取得する際に、取得するデータをフィルタ、並べ替えする目的で使用
＜フィルタ＞
　必要な3要素
　　フィルタを行いたい列の内部名
　　　リストが内部的に持っている値
　　　SharePointリスト：設定→対象の列→URLの「Field=」の右側
　　　列名が日本語である場合は「_x65e5__...」という文字列が内部名に設定される
　　　ODataで使用する場合は「OData_」を先頭につけてこの列名を指定する
　　　ポイント：列の作成は初回は「英語」で（その後日本語で書き直せば煩わしい内部名にはならない）
　　ODataフィルタ演算子
　　フィルタ条件
　使用される演算子　※ワイルドカードは対応していないが、startswithなどの関数を使うことはできる
　　eq(=), ne(<>), gt(>), ge(>=), lt(<), le(<=), and(&&), or(||)
　　数値だったら数値のシングルクォートは削除する
　フィルタクエリ：自分で最初から書く必要がある
　いろいろな形でのフィルタ
　　Title eq 'PApps'
　　Number eq 20                                    // シングルクォートはいらない
　　Date eq '2024-07-29'                            // シングルクォート必要＋「yyyy-MM-dd」形式
　　DateTime eq '2024-07-29T12:34:00'               // シングルクォート必要＋「yyyy-MM-ddThh:mm:ss」形式、末尾に「Z」をつけるとUTC扱い
　　　　　　　　　　　　　　　　　　　　　　　　　     SPOListでは時間は分までしか持てないため、「ss」部分は必ず「00」になる
　　YesNo eq 0                                      // Yes/No型の場合、Yes=1, No=0　「eq true」とかはできない
　　Choice eq 'Choice1' and Choice eq 'Choice3'     // 複数選択肢の場合は「and」でつなぐ
　　Attachments eq 1                                // 固定名。添付がある場合は1、ない場合は0
　　User/EMail eq 'aaa@bbb'                         // 「/EMail」は固定名。「EMali」の大文字小文字注意
＜並べ替え＞
　必要な2要素
　　フィルタを行いたい列の内部名
　　OData OrderBy クエリ(asc, desc)
　　　Number asc, Title desc

クエリパラメータ
　SharePoint RestAPI、Microsoft Graph APIで利用可能な、ODataクエリオプション
　取得したデータをカスタマイズできる
　SharePoint Rest API
　　PowerAutomateのアクションや関数にないことをSharePointにRest要求、SharePoint側に期待した行動をさせる
　　PowerAutomateでこれを行うには「SharePointにHTTP要求を送信します」を利用
　Graph API
　　M365, AzureADの情報を取得・更新する
　　PowerAutomateでこれを行うには、例えば「Office365 Groups」の中の「HTTP要求を送信します」を利用するなど
　　「Microsoft Graph Explorer」を使用してAPIのテストをすることができる
　書き方
　　それ専用の場所はなく、「URI」の末尾に追記する形で要求を出す

予定表の取得
　コネクタ「Office 365 Outlook」を利用
　自分自身の予定の取得
　　カレンダーの取得
　　　Outlookの「個人用の予定表」にある「カレンダー種別」を取得
　　イベントの取得(V3)
　　　カレンダーに登録されている特定のイベントを取得
　　　　予定表ID：取得する対象のカレンダーのID、選択可
　　　　項目ID：取得する対象の予定に設定されているID
　　　　取得される時間がUTCなので注意
　　イベントのカレンダービューの取得(V3)
      特定の予定表の、開始時刻(UTC)、終了時刻(UTC)でフィルタをかけた内容のすべての予定を取得
　　　フィルタクエリ指定可能
　　イベントの取得(V4)
　　　特定の予定表のすべての予定を取得
　　　フィルタクエリ指定可能
　他の人の空き時間を取得
　　会議の時間を検索(V2)
　　　他の人の空き時間を取得
　　　　必須出席者・任意出席者：対象とする人の情報、複数ある場合はメールアドレスをセミコロンで繋げる
　　　　会議の継続時間：会議時間、省略時は30が代入される
　　　　開始時間・終了時間：UTCで指定(yyyy-MM-ddThh:mm:ss.0000000)、省略時はフロー実行日が代入される
　他の人の予定の詳細を取得
　　イベントの取得(V4)
　　　予定表IDにその人の名前を選択

ユーザ情報の取得
　「Office 365 Users」
　　組織内ユーザプロファイルにアクセス、自分だけでなく、組織内ユーザ個人のプロファイルも取得可
　　　・マイプロフィールの取得：フロー実行者のプロフィール
　　　・上司の取得：M365では上司は1人しか設定できないため、1人分の情報が返される
　「Office 365 Groups」
　　組織内グループメンバーとカレンダーイベントを取得、グループに対して使用する
　　　「グループの一覧」：Teamsに作成されているグループを取得
　　　「HTTP要求を送信する」：標準アクションでは対応していない操作を、RestAPIを用いて実施

パフォーマンス向上のために
　PowerAutomate：契約によって1日どれだけフローを稼働させることができるかが決まっている
　コンテキスト（実行権限）の消費
　　スケジュール実行タイプ：開発者のコンテキストが消費される
　　トリガー実行タイプ：実行者のコンテキストが消費される
　　例外的に、Dataverseのアクションを使用する場合は誰のコンテキストを消費するかを選べる
　ステップの数も評価対象になるため、できるだけ少ないアクションが求められる
　トリガー条件の設定
　　トリガーに対して、実行時条件（トリガー条件）を指定することで、無駄な処理を省ける
　　トリガーの三点リーダ→設定の中に記載する場所がある
　　参考）https://qiita.com/h-nagao/items/46d5d95cfacb3c70841b
　　　例）あるファイルの更新時にフローを実行するとき
　　　　誤：SPO上のファイルが更新→更新されたファイル名の中に「Target」と入っていれば→…
　　　　正：トリガー条件に、例えば「@greater(indexOf(triggerBody()['Title'], 'Target'), 0)」と入力
　トリガーの最適化
　　フローを同時実行できる数を制御する（溢れた分はキューに入り、逐次処理されていく）
　　トリガーの三点リーダ→設定の中に記載する場所がある
　　ここを1にすると強制直列処理になるので、逐一リストの値を変更するなどのフローには必要なテクニック
　リトライポリシー
　　エラーになったとしても指定回数・秒数でリトライさせることができる
　変数の利用数を少なくするためにオブジェクトを用いる
　　変数を初期化する→オブジェクト型を選び、「{"var1": "", "var2": ""}」のように記載する
　　値を取り出す場合は、「variables('valName')?['var1']」の記法で取り出す
　並列実行
　　Apply to eachでの並列
　　　Apply to eachの設定→コンカレンシー制御
　　並列処理の追加
　　　アクションとアクションの間で「＋」クリック→「並列処理の追加」クリック
