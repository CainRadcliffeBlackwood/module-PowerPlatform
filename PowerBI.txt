複数ワークシートのデータを取り込み
　１．Excelからデータをインポート
　２．集計対象のシートのうち「1つだけ」にチェックマークをいれ、「データの変換」をクリック
　３．右部「プロパティ」にて名称を適当なものに変更
　４．右部「適用したステップ」より、「ソース」を残しそれ以外をすべて削除
　５．列「Data」より「⇔」「OK」クリック
　６．不要列削除
　７．「1列目をヘッダーとして使用」を2回クリック
　８．必要な列にフィルタをかけ、フィルタを設定、また列名を変更
　９．「閉じて適用」をクリック


SPO上からファイルを取り込む
　ファイルのデータ取り込み
　　特定のファイルのみをBIに反映させたい場合に使用
　　データの取得→詳細→検索に「Web」と入力→「Web」選択→SPO上のファイルパスをURLに指定→接続
　　（ログインできていない場合）組織アカウントからログイン
　　取り込みたいデータにチェックを入れ、「読込」クリック
　フォルダ指定のデータ取り込み
　　複数のファイル、これからファイルが増える予定であるものをBIに反映させたい場合に使用
　　データの取得→詳細→検索に「SharePoint」と入力→「SharePointフォルダー」選択
　　→SPO「ホーム」のURLを指定（フォルダのパスではない）→接続
　　（ログインできていない場合）組織アカウントからログイン
　　指定したSPO配下のファイルがすべて表示されるので、「データの変換」→「Name」列：対象フォルダの中にある1つの任意のファイルでフィルタ
　　→右側「Folder Path」をクリック→下部に表示されるフルパスをコピー→右ペイン「フィルターされた行」を削除
　　→「Folder Path」列を「指定の値に等しい」でフィルタ、先ほどの値を貼り付ける
　　→「Content」列を展開→「ファイルの結合」ダイアログ中の左ペイン「データ」選択→「OK」クリック
　　→複数のファイルのデータがまとまっていることを確認、「閉じて適用」クリック

データソースの変更
　ローカルのデータソースを変更
　　ホーム→データの変換→データソース設定
　　該当のファイルをクリックした状態で、「ソースの変更」クリック
　　新ファイルを参照し、OKクリック
　データソースの変更をPowerQueryで行う場合
　　ホーム→データの変換でPowerQueryを開く
　　右カラムより「ソース」選択、数式バーを広げる
　　ファイル取り込み方を理解する
　　　= Excel.Workbook(File.Contents(Path, ...  　：ローカルのExcel
      = Excel.Workbook(Web.Contents(Path, ...     ：Web上のExcel
      = Folder.Files(Path, ...                    ：ローカルフォルダ
　　　= SharePoint.Files(Path, ...                ：SPO上フォルダ
　　　= SharePoint.Tables(Path, ...               ：SPOList
　データソースをローカルからWebに変更する
　　１．SPO上の任意のデータソースファイルのパスを取得、コピーする
　　２．ホーム→データの変換でPowerQueryを開き、右カラムより「ソース」選択、数式バーを広げる
　　３．「File.Contents...」→「Web.Contents...」に書き換え、さらにパスを貼り付ける
　　４．「閉じて適用」クリック
　フォルダ単位で、データソースをローカルからWebに変更する
　　１．SPO上の任意のデータソースフォルダのパスを取得、コピーし、URLデコーダにかけてデコードしておく
　　２．ホーム→データの取得→SharePointフォルダーを選択
　　３．SharePointのホーム画面ページのURLを指定、OKクリック→データの変換クリック
　　４．新しいクエリが作成されているので、その右カラムより「ソース」選択、数式バーの値をコピー
　　５．左カラムより、現在のローカルフォルダから読んだデータソースを選択する
　　６．その右カラムより「ソース」選択、コピーした値を数式バーに貼り付ける
　　７．右カラム「ソース」が選択された状態で右側「Folder Path」をクリック、「指定の値で始まる」でフィルタ、１でデコードしたURLを貼り付ける
　　　　　このURLの末尾に「/」を追加：そのフォルダのサブフォルダは含まない
　　８．左カラム「ヘルパークエリ」より「サンプルファイル」をクリック、同様にソース変更、フィルタ処理を実行する
　　９．新規作成された「クエリ1」を削除


単数のソースファイルの最終更新日を項目として取得
データの取得→空のクエリ
表示→詳細エディタで以下の内容を入力
let
    relativePath = "/sites/msspo/Shared Document/(日本語部分そのままのSPO上ディレクトリ)/(ファイル名+拡張子)",
    baseSite = "https://(テナント).sharepoint.com/sites/msspo",
    Source = Json.Document(
        Web.Contents(
            baseSite,
            [
                RelativePath = "/_api/web/GetFileByServerRelativeUrl('" & relativePath & "')",
                Query = [ #"$select" = "TimeLastModified" ],
                Headers = [ Accept = "application/json;odata=nometadata" ]
            ]
        )
    ),
    ModifiedDateTimeJST = DateTimeZone.RemoveZone(DateTimeZone.SwitchZone(DateTimeZone.FromText(Source[TimeLastModified]), 9))
in
    ModifiedDateTimeJST



ドリルダウン・ドリルアップ・ドリルスルー
　ドリルダウン・ドリルアップ
　　グラフの階層を上げ下げする
　　機能を使用するためには、グラフの軸に「階層順」にデータを入れておく必要あり
　　　ドリルダウン：日本→都道府県→市区町村...
　　　ドリルアップ：...市区町村→都道府県→日本
　　グラフ上部にボタンが存在
　　　二重下矢印（↓↓）
　　　　x軸の階層を1つ下げる、通年のデータは全てまとめられるので注意
　　　ドリルダウン（↓）
　　　　その項目のx軸の階層を1つ下げる
　　　展開
　　　　そのx軸項目を保ったまま、さらに1階層下の情報も表示する
　　　ドリルアップ（↑）
　　　　ドリルダウンの逆の動き、階層を1つ上げる
　ドリルスルー
　　その詳細を別ページに示す
　　あらかじめ別ページに用意した詳細リストをグラフから呼び出す形


パラメータ
　PowerBI内で使用できる、定数的に使用できる変数
　設定方法
　　ホーム→データの変換（PowerQueryを表示）
　　表示→パラメータ「常に許可」にチェック
　　ホーム→パラメータの管理→新しいパラメータ
　　名前、種類、現在の値を設定→「閉じて適用」クリック
　(Web上から取り込んだ場合)データソースのURLをパラメータ化した場合の反映方法
　　ホーム→データの変換→データソース設定
　　ソースの変更→URLの「ABC」アイコンをクリック→「パラメーター」を選択
　(SPOフォルダ上から取り込んだ場合)データソースのURLをパラメータ化した場合の反映方法
　　前半はWebと設定方法は同じだが、とってくるURLはSPOの「ホーム」をクリックした時のURL
　　これがWebのURLを格納するためのパラメータになる
　　PowerQueryを開いた状態で、右ペイン「フィルターされた行」クリック
　　「Folder Path」の値をコピー、それを値としたパラメータを新規で作成
　　PowerQueryを開いた状態で、右ペイン「フィルターされた行」の歯車マークをクリック
　　「ABC」アイコンをクリック→「パラメーター」を選択
　　これがフィルタのためのパラメータになる
　(SPOListから取り込んだ場合)データソースのURLをパラメータ化した場合の反映方法
　　SPOListのIDをパラメータ化する
　　SPOListを開き、設定アイコン→リストの設定→そのURLの「%7B」から「%7D」の間の値をパラメータ設定する
　　PowerQueryを開いた状態で、右ペイン「ナビゲーション」をクリック
　　数式バーの、IDが入っているところとその「""」を削除し、パラメータ名をセット
　(Excelファイルから取り込んだ場合)データソースのパスをパラメータ化した場合の反映方法
　　PowerQueryを開いた状態で、右ペイン「ソース」の歯車マークをクリック
　　「ABC」アイコンをクリック→「パラメーター」を選択




DAX関数
　高度な演算をするための関数群
　基本構文
　　「変数/列名/メジャー/テーブル名 = DAX関数(引数)」
　新しいメジャーを作成

DAX関数いろいろ
　SUM(テーブル名[列名])
　　そのテーブルのその列を合計したメジャーを作成する
　DIVIDE(テーブル名1[列名], テーブル名2[列名], 0除算時のエラー表示)
　　テーブル1の内容をテーブル2で割った列を作成する
　CALENDER(開始日, 終了日)
　　開始日から終了日までの日付を示すテーブルを作成する
　CALCULATE(DAX式, フィルタ条件1, フィルタ条件2, ...)
　　指定したフィルタ条件によってフィルタされたテーブルに対してDAX式を実行
　　例：CALCULATE(SUM(tbl1[col1]), tbl1[col2] = 'cat')
　SUMMARIZE(ベーステーブル, 集計列1[, 集計列2, ...], 集計対象列1, DAX式1[, 集計対象列2, DAX式2 ...])
　　ベーステーブルから、集計列ごとに、集計対象列をDAX式で集計したテーブルを作成する
　RANKX(テーブル, DAX式/テーブル名[列名][, オプションDAX式][, オーダー(ASC/DESC)][, 同点処理(Skip/Dense)])
　　テーブルの、指定した列に対するランクづけを行うための列を作成する
　　同点処理は、3位が2人いた場合、Skipなら次は「5」、Denseなら「4」となる

PowerAppsと連携
PowerBIの中にPowerApps（PowerAppsビジュアル）を埋め込む
　利点
　　レポートから直接データソースを更新
　　レポート操作によって変化するアプリ
　PowerBIへの追加方法
　　視覚化→「Power Apps for Power BI」を選択
　　PowerBIからPowerAppsを開くか新規作成するかの画面が表示されるので、クリック
　　PowerAppsが起動し、左ペインに「PowerBIIntegration」が追加される
　　　この項目：PowerBIから取得したデータ
　　　呼び出す際：PowerBIIntegration.Dataのように記載することで呼び出せる
　　　　.Data ... 全データを呼び出す
　PowerBI-PowerAppsがリアルタイムで反映されるために
　　接続方法「DirectQuery」を使用（ただしDataverseのみサポート、SPOListは使用不可）
